Project Overview & Functional Scope

Domain Scope

The platform unifies 6 core health and wellness domains into a centralized tracking suite:

1. Activities & Workouts

Running, Cycling, Strength, HIIT, Yoga. Tracks duration, calories burned, distance, steps, and HR intensity zones.

2. Body Measurements

Weight, Height, Body Fat %, Muscle Mass. Automatic BMI classification and Waist-to-Hip ratio (WHR) risk profiling.

3. Vitals & Biometrics

Heart Rate BPM, Resting HR, Blood Pressure (AHA staging), SpO2 oxygen saturation, blood glucose, and temperature.

4. Nutrition & Hydration

Daily meal diary (Breakfast, Lunch, Dinner, Snacks), Macronutrients (Protein, Carbs, Fats), and one-click water logger.

5. Sleep Architecture

Deep, Light, REM, Awake staging. Algorithmic 0–100 Sleep Recovery Score and Canvas Hypnogram visualization.

6. Menstrual & Cycle Tracking

4-phase cycle tracking (Menstrual, Follicular, Ovulation, Luteal), fertile window forecasting, and symptom logging.

OOP: Multi-Level Inheritance

Rubric: 10 Marks

The project adheres strictly to Object-Oriented Design principles with a robust multi-level inheritance hierarchy:

Class Hierarchy (Inheritance)
BaseEntity (abstract)
│   ├── id, createdAt, updatedAt
│   ├── abstract void validate()
│   └── abstract String getEntityType()
│
├── UserProfile
│
└── HealthMetric (abstract) implements Trackable
    ├── timestamp, notes, validation logic
    │
    ├── Activity
    ├── BodyMeasurement
    ├── Vital
    ├── NutritionLog
    ├── SleepSession
    └── CycleLog
OOP Design Benefits
  • Code Reusability: Common identity, lifecycle timestamps, and notes fields are inherited from BaseEntity and HealthMetric.
  • Template Method Pattern: Base classes enforce the validate() contract across every derived model.
  • Extensibility: New biometric trackers (e.g. ECG logs, Stress sessions) can be added simply by extending HealthMetric.

OOP: Polymorphism & Interfaces

Rubric: 10 Marks
Interface: Trackable

Enforces a universal contract across disparate health events: 

public interface Trackable {
    String getTimestamp();
    String getCategory();
    double getPrimaryMetricValue();
    String getSummary();
}

Implemented polymorphically by Activity, BodyMeasurement, Vital, etc.

Dynamic Method Dispatch in Action

Polymorphic collections processing different log types uniformly: 

List<Trackable> metrics = List.of(
    new Activity("Jogging", ...),
    new Vital(72, ...),
    new BodyMeasurement(62.4, ...)
);

for (Trackable t : metrics) {
    // Dynamically dispatched at runtime
    System.out.println(t.getSummary());
}

OOP: Custom Exception Hierarchy

Rubric: 10 Marks
Domain Exception Hierarchy
FitnessException (Base Checked/Domain Exception)
│
├── ValidationException
│   └── (Triggered on invalid biometric ranges)
│
├── EntityNotFoundException
│   └── (Triggered on missing IDs during query)
│
└── DatabaseException
    └── (Triggered on JDBC or connection failures)
Robust Error Handling & Propagation
  • Pre-condition Verification: All entities validate input ranges (e.g. Heart Rate between 20-250 BPM, positive duration).
  • Graceful Recovery: REST Controllers intercept custom exceptions and return structured JSON error payloads (400 Bad Request, 404 Not Found, 500 Internal).
  • Error Codes: Exceptions carry dedicated machine-readable error codes (VALIDATION_FAILED, ENTITY_NOT_FOUND).

Collections & Generics Design

Rubric: 6 Marks
Generic Repository Interface
public interface Repository<T extends BaseEntity, ID> {
    T save(T entity);
    Optional<T> findById(ID id);
    List<T> findAll();
    boolean deleteById(ID id);
    
    // Generic Functional Queries
    List<T> filter(Predicate<T> predicate);
    List<T> findSorted(Comparator<T> comparator);
}
Collections Implementation
  • ConcurrentHashMap<ID, T>: High-performance thread-safe storage engine supporting concurrent access.
  • Java Generics with Bounds: <T extends BaseEntity, ID> ensures compile-time type safety.
  • Stream API & Lambdas: Filter by criteria (e.g. high-intensity workouts) and sort by custom Comparators (e.g. calories burned descending).

Multi-User Database Design & 3NF Schema

Relational Database

Fully normalized Third Normal Form (3NF) relational SQLite schema with strict multi-user data segregation (data/schema.sql):

users (Multi-User Accounts)

Primary Key: id. Manages user accounts, unique emails, avatar colors, biometric baselines, and individual daily targets.

activities (User Segregated)

FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE. Duration, distance, calories, heart rate zones, steps.

body_measurements

FK: user_id. Weight, height, BMI, body fat %, waist, hips, biceps, thighs, waist-to-hip ratio.

vitals & biometrics

FK: user_id. Heart rate, resting HR, BP systolic/diastolic, SpO2, glucose, temp, HR zones.

nutrition_logs

FK: user_id. Meal type, calories, protein, carbs, fats, fiber, water tracking.

sleep_sessions & cycle_logs

FK: user_id. Hypnogram sleep architecture stages and 4-phase menstrual cycle tracking with ovulation forecasts.

Database Connectivity (JDBC)

JDBC Integration
Singleton Connection Pattern
public class DbConnectionFactory {
    private static volatile DbConnectionFactory instance;

    public Connection getConnection() throws DatabaseException {
        try {
            return DriverManager.getConnection(
                DatabaseConfig.DB_URL
            );
        } catch (SQLException e) {
            throw new DatabaseException("Connection error", e);
        }
    }
}
PreparedStatements & Resource Management
  • SQL Injection Prevention: Parameterized PreparedStatement objects across all write and read queries.
  • AutoCloseable Resources: Standard try-with-resources blocks preventing JDBC connection and cursor leaks.
  • Dual-Mode Fallback: Supports pure-Java JSON serialization and high-performance SQLite JDBC execution.
